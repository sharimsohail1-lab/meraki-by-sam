# ARCHITECTURE.md — Meraki by Sam

## Stack

| Layer | Technology | Reason |
|-------|-----------|--------|
| Frontend | Single HTML file, vanilla JS | No build pipeline, no npm, no deployment friction |
| Backend | Vercel serverless functions (Node.js ES modules) | Zero-ops, free tier, auto-deploy on git push |
| Database | Supabase PostgreSQL | Managed, free tier, REST API |
| AI | Anthropic Claude (claude-sonnet-4-6) | Vision + text, best garment analysis quality |
| Image gen | Ideogram v4 | Best quality for fashion/garment photos |
| Hosting | Vercel | Free, auto-deploys from GitHub |
| Fonts/Icons | Google Fonts + Tabler Icons (CDN) | No local assets to manage |

---

## Frontend Architecture

**Single file:** `index.html` — all HTML, CSS, JavaScript. Currently ~3000+ lines. No build step.

**Navigation:** Bottom tab bar (5 tabs: Home, Stock, Add, Customers, Exhibitions)

**Overlays:** Bottom sheets (`.sheet-overlay` → `.sheet`) for all detail views and wizards

**State:** Module-level variables. No reactive framework. No state management library.

**DOM:** Direct manipulation (`innerHTML`, `textContent`, `classList`). No virtual DOM.

**PWA:** `<meta name="apple-mobile-web-app-capable">` + `<meta name="theme-color">` set. No `manifest.json`. No service worker. Cannot be properly installed on Android.

## Backend Architecture

Four Vercel serverless functions in `api/`:

### `api/db.js`
Unified CRUD proxy to Supabase.

```
POST body: { action, table, id, data, filter }
actions: 'insert' | 'update' | 'select' | 'delete'
```

Uses `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` from env vars. Service key never reaches frontend.

### `api/claude.js`
Proxy to Anthropic Messages API.

```
POST body: { messages, system, max_tokens }
```

Injects `ANTHROPIC_API_KEY` from env. No streaming. Returns raw API response.

### `api/ideogram.js`
Proxy to Ideogram v4.

```
POST: multipart/form-data with text_prompt field → generation
GET ?url=...: proxies image to bypass CDN CORS (for Canvas watermarking)
```

Uses `IDEOGRAM_API_KEY` from env. v4-specific: prompt goes as direct `text_prompt` field (not `image_request.prompt`).

### `api/migrate.js`
Migration runner. Reads `migrations/*.sql` in sort order, runs each statement, tracks in `migrations` table. Protected by `x-migration-secret` header matching `MIGRATION_SECRET` env var.

## Database Schema

Full schema in `migrations/001_initial.sql`. Migrations 002 and 003 add marketing/catalog fields.

Key decisions:
- **RLS disabled** — intentional for single-user app. Service key is server-side only.
- **Photos as base64** in `products.photo` and `products.model_photo` — known scaling problem. Will degrade after ~50-100 products. Migration to Supabase Storage is on the roadmap.
- **collection_name is TEXT** — comma-separated for multi-collection support. No junction table. Simple and sufficient.
- **No updated_at trigger** — column exists, never set by app.

### Products table (key fields)

```
id UUID PK
sku TEXT UNIQUE             -- MRK-{TYPE}-{SEASON}{YEAR}-{SEQ}
name TEXT
garment_type TEXT           -- full-suit | kameez | lehenga | dupatta | other
season TEXT                 -- eid | wedding | summer | winter | casual | formal
colors TEXT
occasion TEXT
category TEXT
description_en TEXT
description_ur TEXT         -- never populated currently
price INTEGER               -- USD
cost INTEGER                -- USD (converted from PKR if needed)
status TEXT                 -- available | reserved | sold
reserved_for TEXT
photo TEXT                  -- base64 data URL (primary display photo)
model_photo TEXT            -- base64 data URL (AI-generated, not saved to DB yet)
ideogram_prompt TEXT        -- surgical prompt for Ideogram, generated by Claude
caption_en TEXT             -- Marketing Package fields →
caption_ur TEXT
story_text TEXT
hashtags TEXT
whatsapp_listing TEXT
price_card TEXT
sharing_angle TEXT
catalog_blurb TEXT
collection_name TEXT        -- comma-separated, e.g. "Eid 2026, Summer Shadi"
notes TEXT
created_at TIMESTAMPTZ
sold_at TIMESTAMPTZ
```

## AI Integration

### Claude
- Model: `claude-sonnet-4-6` (hardcoded in frontend `callClaude()`)
- Uses: garment analysis (vision), marketing package, WhatsApp messages, Instagram captions, customer suggestions, collection name suggestions, WhatsApp catalog
- Every call is stateless (no conversation history)
- Max tokens varies: 200 (collection names) → 1200 (marketing package)

### Ideogram v4
- Endpoint: `https://api.ideogram.ai/v1/ideogram-v4/generate`
- Aspect ratio: `ASPECT_2_3` (portrait, garment-appropriate)
- Prompt: surgical English text generated by Claude during garment analysis
- Watermarking: Canvas API client-side, Meraki logo base64 (~440KB embedded in HTML)

## Image Storage Problem

**Current state:** Photos stored as base64 strings in Supabase `TEXT` columns. A 6-photo full suit adds ~1.2MB to the database row.

**Impact timeline:**
- 0–30 products: no noticeable impact
- 30–100 products: queries slow, app startup slows
- 100+ products: real degradation; possible Supabase row size limits

**Solution (not yet implemented):** Migrate to Supabase Storage. Upload photos to a bucket, store the public URL. Requires:
1. New Supabase Storage bucket (`product-photos`)
2. Modify intake wizard to upload file → get URL → store URL (not base64)
3. Migration for existing products (out-of-scope until needed)

## Deployment

- GitHub repo: `sharimsohail1-lab/meraki-by-sam`
- Auto-deploy: Vercel watches `main` branch
- No CI/CD pipeline beyond Vercel automatic deployment
- No staging environment

**Env vars in Vercel:**
- `ANTHROPIC_API_KEY`
- `IDEOGRAM_API_KEY`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_KEY`
- `MIGRATION_SECRET`

**Network note:** The remote Claude Code container cannot make outbound HTTPS calls to Vercel URLs due to network policy. All Vercel/API testing must be done by Sam or via Hoppscotch.

## Known Technical Debt

1. Base64 photos in DB (critical, see above)
2. No service worker / offline support
3. No manifest.json (can't install as true PWA on Android)
4. SKU sequence based on `inventory.length` — can collide across sessions
5. `model_photo` never saved to DB (only in memory)
6. `updated_at` column never written
7. Settings modal is vestigial (API key field does nothing)
8. No search/sort on stock screen
9. No soft delete / archive
10. Urdu font (Nastaliq) referenced in CSS but not loaded
